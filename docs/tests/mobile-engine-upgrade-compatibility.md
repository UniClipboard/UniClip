# 移动端 Engine 升级兼容性测试方案

## 1. 文档状态

- 状态：测试设计完成，等待移动端产品适配 Engine 后执行
- 制定日期：2026-08-15
- 上一个正式移动版：`v1.3.0.165`
- 目标移动版：待适配候选版，版本号和构建号尚未确定
- 目标 Engine 基线：`v1.1.0-rc.2`，提交 `49976d5ea21c5d448d9ef5df2c581b77abeb52cf`，或其后明确包含同等兼容修复的版本

本文不是测试结果，也不表示移动端产品已经完成 Engine 适配。它定义适配完成后必须怎样验证：用户从上一个正式版原地升级，已有数据、空间、设备关系和同步能力仍然可用。

## 2. 验证目标

本轮验证回答五个问题：

1. 正式版 `v1.3.0.165` 能否不卸载、不清数据地升级到候选版。
2. 旧设置、历史记录、图片和文件缓存是否保留，且不会重复、错配或被默认值覆盖。
3. 旧用户进入新的 Engine 空间流程时，是否得到明确、可完成的迁移或重新配对引导。
4. 已有 Engine 空间能否完成设备信任迁移，旧空间加载失败问题是否消失。
5. 升级后重启、前后台切换、离线恢复和多设备收发是否仍然正确。

安装成功、应用能启动、首页能显示都不等于兼容性通过。必须验证原数据可读、状态可继续演进，并由接收设备证明内容实际到达。

## 3. 范围与边界

### 3.1 本轮包含

- iOS 和 Android 正式版原地升级。
- iOS App Group、钥匙串、数据库、历史记录和扩展共享数据。
- Android 应用数据、设置、数据库、权限和后台能力。
- 无空间、旧连接、单设备空间、多设备空间、离线成员和待处理设备变化。
- 文本、图片、小文件和大文件的升级前保留与升级后双向收发。
- 首次启动、迁移中断、强制终止、再次启动和前后台恢复。
- 新旧版本短期并存时的兼容提示和安全行为。

### 3.2 本轮不包含

- 全新安装的完整功能验收；全新安装只作为对照组。
- 性能压测、长时间耗电测试和商店审核流程。
- 通过清空数据、重新建空间或重新安装来掩盖升级失败。
- 由移动端猜测、修补或重算 Engine 的成员关系和设备信任结果。

## 5. 测试数据样本

每个原地升级用例从下列固定样本之一开始。样本建立后记录数量、内容哈希和关键设置，不记录真实设备名称、完整设备编号、账号或用户内容。

| 样本                | 升级前状态                   | 必须包含                                                             |
| ------------------- | ---------------------------- | -------------------------------------------------------------------- |
| D0 空白用户         | 已完成安装但未配置           | 无历史、无旧连接、默认设置                                           |
| D1 旧连接用户       | 正式版正常使用中的旧同步连接 | 一个有效连接、一个失效备用地址、非默认自动同步设置                   |
| D2 丰富历史         | 正式版持续使用至少 24 小时   | 20 条文本、5 张图片、3 个文件、收藏和删除记录、重复内容              |
| D3 缓存边界         | 本地缓存同时有可用和缺失内容 | 已缓存图片、已缓存文件、仅远端可取内容、文件名含中文和空格           |
| D4 自定义设置       | 多项设置偏离默认值           | 深浅色、语言、自动同步、附件下载、更新、日志和平台专属设置           |
| D5 已有 Engine 空间 | 由受支持的工程夹具生成       | 旧格式加密空间、有效成员表和历史；原始数据必须保留                   |
| D6 异常 Engine 空间 | 由受支持的工程夹具生成       | 可迁移旧状态、明确不支持状态、损坏状态各一份，禁止手工改线上用户数据 |

每个样本至少保留一份可重复恢复的设备备份或自动化夹具。失败后从样本重新开始，不能在失败后的半迁移数据上继续下一个用例。

## 8. 单个用例执行流程

每个用例按同一顺序执行：

1. 安装源版本并确认版本号、应用标识和安装来源。
2. 建立指定数据样本，记录升级前数量、设置值、内容哈希和设备关系摘要。
3. 完全退出应用；不得卸载、清数据或手工移动存储文件。
4. 使用相同生产应用标识覆盖安装候选包。
5. 在首次启动前开始采集脱敏系统日志和应用日志。
6. 首次启动，完成用例指定的迁移、配对或设备决定。
7. 核对历史、设置、缓存、空间和设备关系。
8. 强制终止后冷启动两次，再次核对相同结果。
9. 执行发送与接收动作，由接收设备保存结果或打开内容作为交付证明。
10. 导出脱敏诊断包，填写结果和证据位置。

迁移失败时立即停止该用例并保留现场。禁止通过重装、清缓存、重建空间或重新配对后继续填写“通过”。

## 9. 证据要求

每个 P0、P1 用例必须保留：

- 源版本、候选版本、两边提交和 Engine 版本。
- 设备平台、系统版本、安装方式和用例开始/结束时间。
- 升级前后的历史数量、设置快照摘要和内容哈希对照。
- 首次启动、第二次冷启动和关键决定界面的截图或录屏。
- 脱敏日志；不得包含设备名称、完整设备编号、账号、令牌、空间编号或用户内容。
- 多设备用例的接收方结果；只记录发送方状态不算交付证据。
- 失败现场的原始数据备份编号和错误类别，不能只写“空间加载失败”。

## 10. 自动化与人工验证分工

### 10.1 适配完成前必须补齐的自动验证

- 用 165 真实序列化样本验证设置迁移，不允许默认值覆盖旧值。
- 用文本、图片、文件、删除项和重复项样本验证历史迁移及重复执行。
- 用旧 Engine 空间夹具验证成功迁移、迁移中断恢复、明确不支持和损坏状态。
- 验证启动、回前台、变化事件和决定完成后都重新读取完整空间状态。
- 验证读取乱序、决定与刷新并发、重复点击和下一项变化。
- 验证 iOS 与 Android 对同一 Engine 结果采用相同业务含义。
- 验证生产候选包仍使用正式应用标识和原存储容器，开发包仍与正式数据隔离。

### 10.2 必须人工真机完成

- 生产标识原地覆盖安装。
- iOS App Group、钥匙串、键盘和分享扩展。
- Android 权限、后台行为和覆盖安装。
- 三台真实设备上的设备信任决定和新旧版本并存。
- 文本、图片和文件的接收方实际落地。
- 强制终止、系统重启、离线恢复和网络切换。

## 11. 发布门槛

候选版只有同时满足以下条件才能判定“兼容性通过”：

- 所有 P0 用例在 iOS 和 Android 适用平台通过。
- P1 无数据损坏、成员关系错误、错误空间或隐私泄漏；其他失败有明确负责人和发布决策。
- 原地升级不要求用户卸载、清数据或重建本可迁移的空间。
- 可迁移旧空间不再出现原 1393 加载失败。
- 迁移中断后可恢复，重复启动不新增重复数据或重复决定。
- 新旧版本并存时采取明确、安全的限制，不显示虚假在线或错误成员关系。
- 至少一组完整的三设备决定流程通过。
- 文本、图片、小文件和大文件各有接收方完成证据。
- 发布报告明确区分：自动测试、构建、安装、启动、单机验证、多设备验证和正式发布。

以下任一情况直接阻断发布：

- 旧数据被清空、覆盖、错配或只能通过重装恢复。
- 空间或设备列表加载失败但界面继续展示推测状态。
- 本机被错误移出空间、已移除设备被重新加入，或离线被误判为移除。
- 必须决定的设备变化可以绕过，或决定结果在重启后回滚。
- 发送方显示成功但接收方没有收到内容。
- 日志、通知或测试证据泄露设备、空间、账号或用户内容。

最终结论只能使用以下三种状态：

- **通过**：所有发布门槛满足。
- **有条件通过**：仅 P2 或已批准的非数据安全 P1 项未完成，并有明确限制和截止日期。
- **不通过**：任一 P0 失败，或存在数据、成员关系、隐私、强制决定、接收方交付问题。
