# Engine 接收诊断升级验收

## 范围与完成标准

移动端从 `b9b25fb22850733b6a732edce77917935fb01b40` 升级到
`427bd647ac1408118a37f9ee9b851754006b2be3`，采用指定 Engine 工作区的干净提交构建。

完成标准：两端实际构建通过；模拟器从真实页面完成诊断记录、重启、导出；
检查导出包版本和落盘结果；使用独立测试空间验证桌面与模拟器互发及重启后互发。

Engine 的交接明确区分了接收失败原因可观测性的修复与原始单向拒收事故的根因。
本次升级不把缺失更新的自动补偿视为已解决；新空间正常同步也不能证明旧空间自动恢复。

## 适配

- 更新 Engine 来源提交、模块版本及构建产物校验值。
- 此版本没有新增绑定接口；现有移动端导出保留原始 Engine JSONL 字段。
- 修复 Android 加入空间时对话框被重新挂载的问题：加载、空空间和已加入页面共用稳定的对话框位置，避免操作中返回空白邀请码页；回归测试先失败后通过。
- 增加导出回归：普通与详细模式均保留接收失败阶段、固定原因、错误链和关联信息。
- 增加显式选择的联网 E2E，默认离线套件不变。页面由 Maestro 操作，桌面对端使用独立临时空间且不接触系统剪贴板；结束后清理本轮拥有的对端与模拟器。

## 验收边界

验收使用独立临时空间和模拟器，没有修改 Engine / 桌面源码，也没有删除 PostHog 产品日志。
桌面对端使用同版本的 alpha.9 CLI / daemon 和本轮独立临时 profile。
本轮没有复现旧空间的缺失密钥或成员状态冲突，也没有验证真机、分享/键盘扩展、
Android 长时间后台的完整矩阵。拒收字段保留由 ZIP 回归测试验证；普通同步成功不替代这些故障恢复验证。
