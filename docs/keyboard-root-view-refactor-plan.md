# UniClip iOS 键盘显示层解耦重构方案

状态：实施中；阶段 A 已完成，阶段 B 尚未开始。

基线：`e0c365b fix(ios): restore independent keyboard sync`

## 1. 目标

本次重构只处理 iOS 键盘显示层的职责和更新方式，目标是：

- `KeyboardRootView` 不再直接依赖完整的 `KeyboardModel`。
- 显示层不再直接知道 P2P/LAN、`UcEngineCore`、服务器配置或剪贴板数据结构。
- 顶部栏、卡片区、按键区和高度变化彼此独立更新。
- 单张卡片变化只影响对应卡片，不重新配置其他卡片。
- 图片卡片在无内容变化时保留现有缩略图，不重复加载。
- 首批最多显示 20 条，接近末尾时再追加 20 条。
- 用真实行为检查替代依赖源码文字的检查。
- 每个阶段都保持可编译、可运行、可单独提交和回退。

## 2. 非目标

本次不处理以下问题：

- 不修改 `uc-engine`、P2P 协议、LAN 协议和共享历史格式。
- 不改变剪贴板读取策略和系统“粘贴自”提示行为。
- 不重写 `KeyboardModel` 内部的同步状态机。
- 不改主应用和分享扩展的同步流程。
- 不以“把 916 行搬到多个文件”作为完成标准。

## 3. 当前问题

当前 `KeyboardRootView.swift` 同时承担：

- 整体布局和高度计算。
- 五组状态订阅和更新调度。
- 顶部栏、服务器菜单和同步按钮。
- 卡片筛选、列表数据和空状态。
- 卡片点击、图片加载和操作反馈。
- 空格、删除、回车和输入法切换。
- 页面级诊断记录。

它还直接接收完整的 `KeyboardModel`，调用其同步、服务器、文字输入、图片加载和卡片操作方法。当前五个 Presentation 类只是镜像 `KeyboardModel` 的字段，没有形成可替换的显示入口。

最直接的风险是：一个卡片的操作状态变化会重新配置全部卡片；图片卡片随之回到占位图并重新加载。现有 Jest 检查主要匹配源码文字，无法证明未变化的卡片保持不动。

## 4. 目标结构

```text
KeyboardViewController
  |
  | 生命周期、系统输入代理、键盘高度
  v
KeyboardModel
  |
  | 实现唯一的显示接口
  v
KeyboardViewStore  <---- FakeKeyboardViewStore（行为检查）
  |
  | KeyboardViewState + KeyboardViewAction
  v
KeyboardRootView
  |-- KeyboardTopBarView
  |-- KeyboardCardListView
  |     |-- KeyboardStateView
  |     `-- KeyboardCardCell
  `-- KeyboardKeyRowView
```

职责约束：

- `KeyboardViewController` 只管理系统生命周期、输入代理和承载高度。
- `KeyboardModel` 继续拥有同步、历史和卡片业务行为。
- `KeyboardViewStore` 是显示层唯一入口。
- `KeyboardRootView` 只组合三个区域并转发状态和动作。
- 各区域只接收自己的显示数据，不能访问 `KeyboardModel`。
- `KeyboardCardCell` 只接收卡片显示数据和缩略图加载函数。

## 5. 唯一显示接口

### 5.1 状态

新增不可变的 `KeyboardViewState`，由以下独立部分组成：

- `layout`：完全访问、是否显示输入法切换键、返回键标题、目标高度。
- `topBar`：标题、服务器选项、筛选状态、刷新按钮状态。
- `content`：权限提示、空状态、错误状态或卡片列表。
- `cards`：只包含显示需要的字段，不保留 `Clipboard`。
- `strings`：已经准备好的显示文字，不把本地化对象传入视图。

每张卡片只暴露：

- 稳定 ID。
- 类型、标题、副标题和时间。
- 操作中、操作完成状态。
- 缩略图版本标识。

不向显示层暴露：

- `Clipboard`。
- `ServerConfig`。
- `ExtensionSyncTrigger`。
- P2P/LAN 类型。
- 共享数据库或网络对象。

### 5.2 动作

显示层只发送 `KeyboardViewAction`：

- 手动刷新。
- 选择服务器 ID。
- 点击卡片 ID。
- 输入空格、回车或删除。
- 切换输入法。
- 打开设置。

按键声音和震动由 `KeyboardModel` 处理，显示层不需要在每个按钮中重复调用。

### 5.3 接口形状

接口保持四个能力：

1. 提供首帧状态。
2. 发布后续状态。
3. 接收用户动作。
4. 按卡片 ID 加载缩略图。

生产环境由 `KeyboardModel` 实现；行为检查使用 `FakeKeyboardViewStore`。这是一个真实的替换点，不新增只有单一实现的空壳。

## 6. 目标文件

| 文件                            | 唯一职责                                   |
| ------------------------------- | ------------------------------------------ |
| `KeyboardViewState.swift`       | 显示状态、卡片显示数据、用户动作和显示接口 |
| `KeyboardModel+ViewStore.swift` | 将内部状态映射成显示状态，并处理显示动作   |
| `KeyboardLayoutMetrics.swift`   | 键盘尺寸规则，供控制器和根视图共同使用     |
| `KeyboardRootView.swift`        | 组合三个区域、保存上一份状态、分派必要更新 |
| `KeyboardTopBarView.swift`      | 筛选、服务器选择和刷新状态                 |
| `KeyboardCardListView.swift`    | 空状态、卡片列表、增量变化和分批加载       |
| `KeyboardCardCell.swift`        | 单张卡片显示和缩略图生命周期               |
| `KeyboardKeyRowView.swift`      | 空格、删除、回车和输入法切换               |

`KeyboardStateView` 可保留在 `KeyboardCardListView.swift` 内，因为它只服务卡片区域。删除连按按钮可保留在 `KeyboardKeyRowView.swift` 内。不要为每个十几行的小类单独建文件。

## 7. 分阶段实施

### 阶段 A：固定行为和失败信号

状态：已完成（2026-07-28）。已建立可运行的行为检查和运行记录分析，能稳定捕获单张卡片变化波及全部卡片的问题；刷新和非空列表错误不会触碰卡片。模拟器中的显示、刷新、卡片点击和明暗模式已验证，验收时发现的深色背景割裂也已修复。

工作：

- 记录当前首帧、权限、空状态、错误、筛选、服务器菜单、同步按钮、卡片点击、图片加载和按键行为。
- 为显示状态和列表变化建立可运行的 Swift 行为检查。
- 增加两条必须先失败的检查：
  - 单张卡片操作状态变化不能影响其他卡片。
  - 同步按钮或非空列表错误变化不能产生卡片列表操作。
- 保留现有真机诊断回放，补充“每次更新实际配置了哪些卡片”的断言。

退出条件：

- 新检查能稳定捕获当前的全量卡片配置问题。
- 现有同步和真机日志格式不变。
- 不修改产品行为。

### 阶段 B：建立显示接口

工作：

- 新增 `KeyboardViewState`、`KeyboardViewAction` 和 `KeyboardViewStore`。
- 让 `KeyboardModel` 直接实现该接口，不增加转发对象。
- 把服务器选项、本地化文字和卡片显示数据在模型侧准备好。
- `KeyboardRootView` 改为依赖显示接口，不再依赖具体模型。
- 移除 `KeyboardRootView.swift` 对 `UcEngineCore` 的导入。

退出条件：

- 画面和操作与基线一致。
- 根视图中不再出现 `KeyboardModel`、`Clipboard`、`ServerConfig` 或同步触发类型。
- Fake 实现可以驱动权限、空状态、错误和卡片四种画面。

提交建议：`refactor(ios): introduce keyboard view interface`

### 阶段 C：按区域拆分显示

工作：

- 提取顶部栏、卡片列表和按键区。
- 根视图只负责纵向组合、目标高度和把状态送到对应区域。
- 把服务器菜单创建限制在顶部栏。
- 把筛选状态和卡片分页限制在卡片列表。
- 把删除连按任务限制在按键区。
- 将高度规则移入 `KeyboardLayoutMetrics`。

退出条件：

- 每个区域只有一个 `render(state:)` 入口和一个动作回调。
- 任一区域不访问其他区域的视图对象。
- 控制器不再依赖 `KeyboardRootView.swift` 内部定义的常量。
- 当前画面、按键和高度行为不变。

提交建议：`refactor(ios): split keyboard presentation regions`

### 阶段 D：改为局部更新和分批加载

工作：

- 根视图保存上一份状态，只向变化的区域发出更新。
- 卡片列表根据稳定 ID 计算插入、删除、移动和内容变化。
- 卡片操作状态只更新“之前受影响”和“现在受影响”的卡片。
- 非空列表上的错误变化不触碰卡片。
- 同步按钮变化不触碰卡片。
- 图片卡片只有 ID 或缩略图版本变化时才重新加载。
- 首批最多显示 20 条，靠近末尾时每次追加 20 条。
- 新内容插入列表头部时保持当前可见位置，并平滑露出新卡片。

退出条件：

- 单张卡片变化最多配置对应的前后两张卡片。
- 同步按钮变化产生 0 次卡片配置。
- 非空列表错误变化产生 0 次卡片配置。
- 未变化图片的缩略图加载次数保持不变。
- 任意时刻首次列表不超过 20 条，追加批次不超过 20 条。

提交建议：`refactor(ios): isolate keyboard card updates`

### 阶段 E：删除旧结构和脆弱检查

工作：

- 删除五个只镜像字段的 Presentation 类。
- 删除根视图旧的全量 `renderAll`、全量卡片重配和重复状态。
- 将依赖具体函数名和源码文字的 Jest 检查替换为行为检查。
- 只保留适合源码检查的构建约束，例如不加载 SwiftUI、扩展入口和权限配置。
- 删除过期注释和本轮临时诊断。

退出条件：

- 同一状态只有一个事实来源。
- 不存在新旧两套显示状态并行维护。
- 修改内部函数名不会破坏行为检查。
- `KeyboardRootView` 只承担组合和更新分派。

提交建议：`refactor(ios): remove legacy keyboard presentation mirrors`

### 阶段 F：完整验证

自动验证：

- Swift 显示状态和列表变化行为检查。
- 现有键盘定向检查。
- `modules/uc-engine` 原生检查。
- 全量 Jest、排版、类型和静态检查。
- `git diff --check`。
- Xcode 27 模拟器完整构建。
- Xcode 27 真机签名构建。

真机验证：

1. 权限未开启时，提示和设置跳转正常。
2. 空状态、错误状态、筛选和服务器菜单正常。
3. 连续复制 3 次，桌面收到 3 次，当前键盘及时出现 3 张卡片。
4. 每次新内容只产生必要的卡片变化，不重新配置其他可见卡片。
5. 图片缩略图不因同步按钮或其他卡片操作而重载。
6. 滚动超过 20 条时按 20 条逐批追加。
7. 空格、长按删除、回车和输入法切换正常。
8. 主应用关闭时，键盘仍保持当前已验证的独立同步能力。

系统“粘贴自”提示及其系统级画面变化单独记录，不作为本次重构成功或失败的判断。验收只要求应用自身不再额外触发整组卡片或整个键盘更新。

## 8. 必须保留的行为

- 完全访问权限判断。
- P2P/LAN 显式通道选择和无自动回退。
- 键盘可见期间的独立 P2P 会话。
- 主应用关闭时的键盘同步。
- 共享历史和稳定卡片 ID。
- 服务器选择、手动刷新和错误反馈。
- 文本插入、图片复制、缩略图延迟加载。
- 键盘声音、震动和删除连按。
- Xcode 27 构建要求。

## 9. 风险和控制

| 风险                             | 控制方式                                                   |
| -------------------------------- | ---------------------------------------------------------- |
| 重构同时改变同步行为             | 显示接口只映射已有行为，阶段 B/C 不修改同步代码            |
| 新旧状态并存导致顺序问题         | 阶段 E 必须删除旧 Presentation 类，不长期双轨运行          |
| 把所有状态合成一份后再次全量刷新 | 根视图比较各状态分区，卡片列表使用独立变化计划             |
| 图片重复加载                     | 以卡片 ID 和缩略图版本判断，不以配置调用次数判断           |
| 新增过多空壳文件                 | 只有顶部栏、卡片区、按键区形成独立职责；小助手留在所属文件 |
| 测试继续只匹配源码               | 列表变化、状态映射和真机日志必须验证实际结果               |
| Expo 重新生成工程覆盖测试配置    | 不直接手改生成工程；测试入口必须通过仓库脚本或持久插件生成 |
| 一次提交过大难以回退             | 按 B/C/D/E 四个独立提交推进，每次保持可构建                |

## 10. 完成标准

- 根视图不直接依赖同步核心或完整模型。
- 显示层只有一个状态入口和一个动作入口。
- 三个显示区域可以分别变化，互不重新绘制。
- 单张卡片变化不会重置其他卡片及其缩略图。
- 卡片按每批 20 条加载。
- 旧镜像状态和脆弱源码检查已经删除。
- 自动检查、Xcode 27 模拟器和真机构建通过。
- 真机功能验收通过，日志证明没有应用自身造成的整组刷新。
