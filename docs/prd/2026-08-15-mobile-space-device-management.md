# 移动端空间设备管理与 Engine 升级适配 PRD

## 文档状态

- 状态：已确认，待实施
- 日期：2026-08-15
- 产品范围：UniClip iOS 与 Android 移动端
- 目标 Engine：`v1.1.0-rc.2`，或后续包含相同兼容修复的正式版本
- 升级来源：上一移动端正式版本 `v1.3.0.165`
- 相关产品规则：桌面端 `docs/prd/2026-08-13-device-trust-reconciliation.md`
- 相关移动端规格：`docs/specs/002-device-trust-reconciliation.md`
- 相关验收方案：`docs/tests/mobile-engine-upgrade-compatibility.md`

本 PRD 是本轮移动端空间设备管理的产品依据。已有规格与本文件冲突时，以本文件确认的用户行为为准，后续实施规格必须同步更新。

## 一句话定义

升级后的 UniClip 应让用户在手机上清楚看到当前空间里有哪些设备、每台设备能否同步，并安全地完成添加、移除、退出和空间变化确认，同时保证旧用户原有数据与空间可以直接继续使用。

## 背景

Engine 已补齐旧空间升级、设备关系核对、已移除设备隔离和真实在线状态等能力。移动端需要采用这些结果，不能继续把普通离线、版本过旧、空间分开或资料异常都显示成同一种连接问题。

移动端目前有两个空间入口：

- 首页“我的空间”适合快速查看和添加设备，但不承担完整管理。
- 设置中的“空间”具备移除、退出和切换等管理能力，但与首页缺少统一的设备详情路径。

此外，旧版本用户升级后可能带有已有历史、设置、缓存和空间数据。本轮适配不能通过清空数据、重建空间或要求重新安装来掩盖升级问题。

## 目标用户

主要用户是同时使用两台或更多个人设备的人，例如手机、平板和电脑。用户能够识别自己的设备名称，但不应被要求理解内部安全记录、传播顺序或同步协议。

典型情况包括：

- 从上一正式版直接升级，并继续使用原有历史和空间。
- 在首页快速确认哪些设备正在正常同步。
- 进入设备详情检查异常原因或移除不再使用的设备。
- 收到其他设备提出的移除，并决定是否采用这项变化。
- 本机被移出空间后继续使用本地历史。
- 某台设备版本过旧，或设备资料暂时无法安全确认。

## 用户任务

用户需要能够：

1. 快速看清当前空间有哪些设备。
2. 分辨设备离线、需要更新、等待确认和无法验证等不同情况。
3. 查看单台设备的详细状态和当前可执行操作。
4. 明白移除、退出或保留当前空间分别会造成什么结果。
5. 在空间发生变化后，确认最终还能与哪些设备同步。
6. 从旧版本直接升级，不丢失本地内容、设置和已有空间。

## 产品原则

### 用户界面统一使用“空间”

入口、状态、确认和结果统一使用“空间”。不在用户界面中交替使用“空间”和“设备组”，也不展示内部术语。

### 平时安静，重要变化明确处理

普通上线、离线和自动补齐不打扰用户。来自其他设备的移除必须明确处理，不能自动接受，也不能被跳过。

### 在线不等于可以同步

在线情况、是否仍属于当前空间、双方是否认可同一空间和版本是否兼容是不同事实。设备可以在线，但因为空间不同、版本过旧或资料异常而暂停同步。

### 当前空间只展示当前成员

设备一旦确认属于其他空间，或已经被当前空间移除，就不再出现在当前空间设备列表中。产品在决定完成时明确展示结果，但不把其他空间的设备长期混入当前空间列表。

### 用户数据优先保留

升级、退出空间或本机被移除都不能自动删除本地剪贴板历史。无法确认旧空间数据时，保留原数据并准确说明限制，不重建、不覆盖、不伪装成空空间。

### 只提供真实可执行的下一步

能够处理的问题提供明确操作；当前版本没有空间合并或恢复能力时，不展示无效的恢复、重试或一键修复入口。

## 信息架构

### 首页“我的空间”

首页入口承担快速查看：

- 展示当前空间成员及主要状态。
- 提供添加设备入口。
- 点击设备进入统一的设备详情页。
- 不直接放置移除、退出或切换空间等高影响操作。
- 存在重要异常时显示真实状态，不能固定显示“同步正常”。

### 设置中的“空间”

设置入口承担完整管理：

- 展示当前空间整体状态和当前成员。
- 提供添加设备、切换空间和退出当前空间。
- 点击设备进入与首页相同的设备详情页。
- 只展示仍属于当前空间的设备。

### 设备详情页

首页和设置共用同一套设备详情。详情页至少回答：

- 这是哪台设备，是否为本机。
- 设备当前是否在线。
- 是否仍属于当前空间。
- 当前是否可以同步。
- 是否需要更新，或资料是否无法验证。
- 当前有哪些可执行操作。

远端设备在允许移除时，详情页底部提供“移除设备”。本机详情不提供“移除自己”；用户主动离开使用设置页中的“退出当前空间”。

## 用户可见状态

| 状态             | 用户含义                             | 产品行为                                               |
| ---------------- | ------------------------------------ | ------------------------------------------------------ |
| 正常同步         | 设备属于当前空间并可以同步。         | 正常展示，不提醒。                                     |
| 离线             | 设备暂时无法连接，上线后会自动恢复。 | 保留在列表，不警告、不通知。                           |
| 正在更新空间     | 已确认的空间变化正在生效。           | 显示处理中，不宣称所有设备均已完成。                   |
| 需要确认空间变化 | 其他设备提出了尚未由本机确认的移除。 | 显示不可跳过的决定界面并通知。                         |
| 需要更新         | 对应设备版本过旧，更新前暂停同步。   | 保留在列表，首次出现时通知。                           |
| 无法验证设备资料 | 当前无法安全确认设备关系。           | 保留相关设备或空间状态，暂停相关同步，首次出现时通知。 |
| 属于不同空间     | 双方已经作出不同选择，不再互相同步。 | 在结果页说明，随后从当前空间列表移出。                 |
| 已退出原空间     | 本机不再与原空间同步。               | 恢复普通应用使用，保留本地历史和添加设备入口。         |

当多个状态同时存在时，优先展示会阻止同步或需要用户行动的状态，在线情况作为补充信息展示。

## 核心流程

### 流程一：从上一正式版直接升级

用户不卸载应用、不清除数据，直接安装新版本。

升级后必须满足：

- 本地历史、收藏、删除结果、设置、图片和文件缓存继续保留。
- 已有空间能够直接加载并继续演进。
- 可以安全升级的旧空间自动完成升级，不要求用户重建或重新配对。
- 暂时离线的设备不会被误判为已移除、属于不同空间或需要更新。
- 无法支持或已经损坏的数据得到可区分的说明，原数据保持不变。
- 多次冷启动不会重复导入、重复迁移或改变已经完成的结果。

### 流程二：查看和管理设备

用户在首页打开“我的空间”时，先看到当前空间成员和主要状态。点击任一设备进入详情页。

用户从设置进入“空间”时，看到相同的当前成员和状态，并可以进行完整管理。两个入口不能对同一设备给出互相矛盾的名称、状态或数量。

### 流程三：主动移除远端设备

用户从设备详情点击“移除设备”。确认内容必须说明：

- 将移除哪台设备。
- 本机会立即停止向该设备分享新的内容。
- 该设备以后需要通过新的邀请才能重新加入。
- 其他离线设备可能在上线后询问用户是否采用这项变化。

提交后显示“正在更新空间”。本机已经停止信任目标设备时即可结束等待，但不能声称所有离线设备都已完成处理。

完成后展示结果页，说明当前仍可同步的设备和已经离开的设备。用户点击“完成”后返回当前空间列表，已移除设备不再出现。

### 流程四：收到其他设备提出的移除

当本机出现尚未处理的空间变化时：

- 在应用最上层显示不可关闭、不可跳过的决定界面。
- Android 返回键、外部点击和 iOS 下滑手势都不能绕过。
- 用户可以退出整个应用，但再次打开后仍要继续处理。
- 当前运行期间，同一项变化只发送一次系统通知。
- 点击通知回到当前实际需要处理的决定。
- 决定界面必须说明来源设备、目标设备和每个选择的实际影响。
- 只展示当前允许的选择，不提供孤立的“接受”或“拒绝”。

如果有多项变化，每次只处理当前一项。完成后重新读取结果，再显示下一项，移动端不自行排序、合并或跳过。

### 流程五：采用其他设备提出的变化

用户选择采用变化后：

- 目标设备不再与本机同步新的内容。
- 如果目标包含本机，动作改为“退出这个空间”，并进行第二次明确确认。
- 完成后展示结果页，说明本机是否已退出以及当前仍可同步的设备。
- 用户点击“完成”后返回正常应用界面。

本机退出后可以继续查看、搜索、复制和删除已有本地历史。旧历史不会继续发送给原空间，也不会自动发送到以后加入的新空间。

### 流程六：保留当前空间

用户选择保留当前空间前，必须进行第二次确认，并明确说明：

- 本机不会移除当前仍信任的目标设备。
- 已经采用另一项变化的设备不会撤销自己的决定。
- 双方将属于不同空间，并停止分享新的内容。
- 本机只会继续与仍属于当前空间的设备同步。

完成后展示结果页。用户点击“完成”后，属于其他空间的设备从当前空间列表移出。空间分开是可长期保持的正常结果，不持续显示警告或待办数量。

### 流程七：用户主动退出当前空间

设置页保留“退出当前空间”。确认内容必须说明：

- 只有这台手机退出，其他设备继续使用原空间。
- 本机将停止与原空间分享新的内容。
- 本地历史继续可用。
- 以后重新加入需要新的邀请。

确认后展示结果页，再回到未连接其他设备的正常状态。产品不强迫用户立即创建或加入另一个空间。

### 流程八：设备需要更新

只有系统明确确认版本过旧时才显示“需要更新”。普通离线、连接超时或资料异常不能推断为版本问题。

- 另一台设备需要更新时，详情页说明应在那台设备上更新。
- 本机需要更新时，使用应用已有的更新入口。
- 更新前相关设备暂停同步，但不会被移除。
- 更新完成后自动重新检查，不要求重新配对。
- 同一项“需要更新”首次出现时发送一次通知，不重复打扰。

### 流程九：无法验证设备资料

系统明确无法安全确认设备资料时：

- 暂停相关同步。
- 显示“无法验证设备资料”，不显示成离线或网络错误。
- 不展示内部错误内容。
- 保留原空间和本地数据。
- 当前没有可执行恢复动作时，准确说明限制，不展示无效重试。
- 同一项异常首次出现时发送一次通知，不重复打扰。

## 决定结果页

主动移除、采用空间变化、保留当前空间和主动退出完成后，都进入简短结果页。结果页必须：

- 使用“空间已更新”等结果导向标题。
- 说明本机当前是否仍在原空间。
- 列出当前仍可同步的设备。
- 说明哪些设备已经移除或属于其他空间。
- 不声称所有离线设备都已完成处理。
- 提供单一“完成”动作返回。

如果提交期间状态已经变化，结果页或决定界面应显示最新真实结果，不能继续展示过期选择已经成功。

## 系统通知

在已有通知权限下，以下状态首次出现时发送一次通知：

- 有空间变化必须由本机决定。
- 某台设备明确需要更新并因此暂停同步。
- 设备资料明确无法验证并因此暂停同步。

通知规则：

- 不主动为了本功能申请新权限。
- 不包含完整设备标识、空间关系图或用户内容。
- 待决定变化的通知打开决定界面。
- 需要更新或无法验证的通知打开对应设备详情；无法定位单台设备时打开空间管理页。
- 通知不提供直接决定按钮。
- 普通离线、后台重试、用户刚完成的移除、退出或空间分开不通知。

## 本地历史与数据

- 退出空间、本机被移除或空间分开不会删除本地历史。
- 本地历史仍可查看、搜索、复制和删除。
- 退出后不再向原空间发送新内容。
- 旧历史不会自动发送到以后加入的新空间。
- 升级失败或资料无法验证时，不删除、覆盖、重建或静默替换原数据。
- 用户主动执行清理数据的现有功能不受本 PRD 改变。

## 跨平台要求

iOS 与 Android 必须提供相同的产品含义：

- 相同状态使用相同名称。
- 相同决定产生相同结果。
- 首页、设置、详情、决定和结果页承担相同职责。
- 平台差异只体现在符合各自系统习惯的页面、按钮、返回和通知表现。
- 任一平台都不能增加可以跳过强制决定的关闭方式。

## 非目标

- 不提供把两个不同空间自动合并为一个空间的能力。
- 不提供选择一台设备作为“正确答案”并覆盖其他设备的能力。
- 不恢复已经失效的旧成员资格。
- 不合并或补发空间分开期间产生的内容。
- 不建立账号、管理员、固定主设备或远程审批。
- 不让移动端根据在线状态、设备数量、消息到达顺序或版本号自行判断设备关系。
- 不在本 PRD 中规定内部接口、保存格式或实现步骤。

## 约束

- 空间成员、变化来源、选择影响、允许动作和最终同步关系都以 Engine 当前结果为准。
- 每次状态变化后重新读取完整结果，不能依靠移动端保存第二份决定队列。
- 旧数据必须原地升级，不能把清数据、重新安装或重建空间作为正常升级步骤。
- 正式验收必须使用与上一正式版相同的正式应用身份和存储位置。
- 系统通知不可用时，应用内流程仍必须完整可用。

## 验收标准

### 入口与信息一致性

1. 首页“我的空间”可以查看当前成员、添加设备并进入设备详情，不直接提供高影响操作。
2. 设置中的“空间”可以完整管理设备、切换空间和退出当前空间。
3. 首页与设置对同一设备展示相同名称、状态和成员关系。
4. 空间概览存在异常时不会继续显示“同步正常”。
5. 属于其他空间或已经移除的设备不会继续出现在当前空间列表。

### 状态与设备详情

6. 设备详情分别展示在线情况、空间归属、同步能力和版本状态。
7. 普通离线只显示离线，不出现空间变化、需要更新或资料异常警告。
8. 需要更新、无法验证和等待确认不会被“在线”状态覆盖。
9. 本机详情不提供“移除自己”，远端设备只在允许时提供移除操作。

### 移除、退出与空间变化

10. 主动移除前准确说明目标、立即停止分享和重新加入要求。
11. 来自其他设备的移除显示不可跳过的决定界面，重启后仍然存在。
12. 只显示当前允许的选择，重复点击不会产生重复结果。
13. 本机被移除和保留当前空间都需要第二次明确确认。
14. 每项高影响操作完成后显示结果页，再由用户点击“完成”返回。
15. 结果页准确列出仍可同步和已经分开的设备，不夸大离线设备的完成情况。
16. 主动退出只影响本机，其他设备继续使用原空间。

### 通知

17. 待决定变化、需要更新和无法验证首次出现时各发送一次通知。
18. 相同状态不重复通知；普通离线和用户刚完成的操作不通知。
19. 通知不包含敏感详情，点击后进入正确的当前页面。
20. 未授予通知权限时，应用内决定和状态展示仍然完整。

### 升级与数据保护

21. iOS 和 Android 均能从 `v1.3.0.165` 原地升级，不卸载、不清数据。
22. 历史、设置、缓存和已有空间在升级后保持可用且不重复。
23. 可升级旧空间自动完成升级，不再出现原有空间加载失败。
24. 无法支持或损坏的旧状态得到可区分结果，且原数据不被修改或删除。
25. 升级中断后可以继续或安全重试，多次冷启动结果保持一致。
26. 本机退出或被移除后，本地历史仍可正常查看、搜索、复制和删除。

### 真实多设备验收

27. iOS 和 Android 均完成真机原地升级验证。
28. 使用至少三台真实设备验证普通离线恢复、主动移除、采用变化、保留当前空间和本机退出。
29. 每个需要继续同步的结果都由接收设备实际收到并保存内容证明。
30. 每个应该停止同步的结果都在规定时间内由接收设备未收到新内容证明。
31. 决定前后终止并重启应用，待决定变化、最终空间成员和本地历史保持正确。
32. 只有自动检查、页面可打开或发送方显示成功，不能算完成真实多设备验收。

## 成功指标

上线后只记录不含设备身份的结果：

- 用户看到空间变化后完成决定的比例和耗时区间。
- 决定后恢复正常同步的比例。
- 需要更新提示后恢复正常的比例。
- 用户在空间异常期间重复移除、重复邀请或重建空间的比例。
- 从上一正式版升级后出现空间无法加载的比例。

指标不得记录设备名称、完整设备标识、空间关系或剪贴板内容。

## 后续产品范围

以下能力需要未来单独评审，不属于本次适配：

1. 从一台可信设备重新建立共同空间。
2. 空间恢复前逐台展示保留、重新邀请或停止使用的预览。
3. 恢复过程中断、重启和继续执行。
4. 对不同空间期间产生的内容提供人工迁移工具。

在这些能力正式具备之前，产品允许不同空间长期独立使用，并通过普通邀请、退出和切换空间完成后续管理。
