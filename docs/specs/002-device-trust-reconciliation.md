# 规格 002：移动端设备信任核对

## 状态

- 状态：代码交付完成；正式产品验收待 Engine 发布与三台真实设备验证
- 日期：2026-08-14
- 移动端基线：`72cbe142f91a32b4fc86f2ff8d5c3586e8b5b506`
- Engine 开发基线：`6ec8c35c21220c4b41b8be31f235c111b2226e73`
- 权威产品规则：桌面仓库 `docs/prd/2026-08-13-device-trust-reconciliation.md`
- 权威 Engine 契约：Engine `docs/specs/021-device-trust-reconciliation-product-contract.md`

本规格只定义移动端怎样接入既有产品规则和 Engine 契约，不在移动端重算设备关系、变化来源、
选择影响或决定顺序。

## 1. 交付目标

当 Engine 返回尚待本机决定的设备变化时，移动端在应用最上层显示不可跳过的决定界面。用户只能
从 Engine 当前允许的选择中作出决定。决定完成后，移动端采用 Engine 返回的完整新状态，并继续
显示下一项变化或关闭决定界面。

设备列表同时展示长期关系结果。在线情况不能覆盖待确认、资料无法验证、需要更新、不同空间或已
移除等主要状态。

## 2. 所有权

### Engine

Engine 是以下事实的唯一来源：

- 当前变化及编号、来源设备和目标设备；
- 本机是否在移除目标中；
- 两个选择的影响和当前允许的选择；
- 每台设备的在线情况、成员资格、设备组关系、版本兼容和同步关系；
- 决定结果、决定顺序和完整新状态。

### 移动端

移动端只负责：

- 调用完整查询和决定接口；
- 防止旧请求覆盖新状态及重复提交；
- 将 Engine 事实转换成用户文案和平台界面；
- 在启动、回到前台和收到变化提醒时刷新；
- 在已有通知权限下发送不含敏感详情的本地通知；
- 当前运行期间按变化编号去重通知。

## 3. Engine 接入

开发阶段允许把 `modules/uc-engine/core-source.json` 锁定到指定公开提交，并通过现有本地构建流程从
干净、分离的工作树生成 iOS XCFramework 和 Android AAR。锁定内容必须记录完整提交、干净源码
状态和生成物校验值。

开发和模拟器验证不等待正式 Engine 发布。对外交付前，应改为采用包含同一契约或后续兼容契约的
正式 Engine 发布；若尚未发布，交付说明必须把它列为发布边界，不能把开发提交伪装成正式发布物。

移动模块公开：

- `queryDeviceTrust(): Promise<DeviceTrustSnapshot>`；
- `decideDeviceTrustChange(changeId, choice, confirmLocalRemoval)`；
- `EngineEvent` 中的 `deviceTrustChanged`，事件只携带 revision 并触发完整查询。

底层返回 JSON 时，只允许在 `src/platform/engine` 解析并校验一次。应用内使用明确的 TypeScript
联合类型；未知枚举值或结构缺失视为查询失败，不展示推断结果。

## 4. 统一空间状态

`UnifiedSpaceSnapshot` 增加完整 `deviceTrust`。设备信任不是独立状态中心。

完整空间刷新并行读取普通空间信息和设备信任结果。没有空间时使用 Engine 的无空间结果或空值，
不得保留上一个空间的设备信任状态。

当前 Engine 不再公开成员移除进度的主动查询和变化提醒。移动端只展示 `removeMember` 当次返回的
真实结果；后续刷新和重启不会尝试恢复或推断这份进度。长期关系统一以设备信任查询为准。

设备列表以 `deviceTrust.devices` 为关系事实来源。普通设备列表仅在设备信任结果尚不可用时提供现有
兼容显示；两者合并时按稳定设备编号去重，名称和关系以设备信任结果为准。

## 5. 刷新与决定顺序

服务遵守以下规则：

1. 启动、恢复前台、收到 `deviceTrustChanged` 和决定完成后读取完整结果。
2. 每次读取获得单调递增的本地序号；较旧读取的晚返回不得发布。
3. 决定开始时使此前读取失效；决定期间开始的读取不得覆盖决定返回的新状态。
4. 决定返回的完整状态直接发布，不为同一结果先拼接本地状态。
5. 决定失败不自动重试决定，只重新读取；错误保留在决定界面供用户再次操作。
6. 同一时刻只允许一个决定请求；重复点击复用或忽略当前请求。
7. 提交前再次确认变化编号仍是当前编号且选择仍在 `allowedChoices`。
8. `stateChanged`、`alreadyCompleted` 和本机退出确认都采用返回的完整状态。
9. `changeId` 改变时，界面选择重置为新变化允许的首项。
10. 移动端不排序或保存第二份待决定队列。

## 6. 全局决定界面

决定界面位于应用导航之上。存在 `currentChange` 时始终呈现：

- Android 返回键、外部点击和手势不能关闭；
- iOS 不使用可下滑关闭的页面表单；
- 不显示关闭按钮；
- 仅系统终止或用户关闭整个应用可以中断，重启后由 Engine 状态恢复。

界面必须显示：变化来源、目标设备、两个选择各自“继续同步”和“停止同步”的结果。动作使用结果
文案，不使用孤立的“接受/拒绝”。

只有 `allowedChoices` 中的选项可见。本机被移除时，“应用变化”显示为退出当前空间，并在实际提交
时携带明确确认。保留当前设备组需要二次确认。

提交中禁用全部决定按钮。失败后显示错误和重试动作。状态已经变化时说明状态已更新；若仍有新
变化则原地切换，若没有则关闭。

## 7. 设备列表

主要状态优先级按 Engine 的 `syncRelationship` 映射：

1. 等待本机决定；
2. 资料无法验证；
3. 需要更新；
4. 不同空间；
5. 本机或对方已移除；
6. 正常可用或未知，再显示在线/离线。

不同空间、资料无法验证和需要更新的关系保持可见。相同显示名增加稳定设备编号的短后缀，仅用于
当前显示，不另存身份副本。在线状态作为次要事实显示。

## 8. 生命周期与通知

`AppRuntime` 在进入 active 时请求完整空间刷新。后台收到设备信任事件只标记刷新需要；前台或下次
冷启动读取完整结果。

使用 Expo 56 的通知能力，平台代码分别实现，但共享以下策略：

- 不主动申请新权限；仅在权限已允许时发送；
- 每个运行周期对同一变化编号最多通知一次；
- 通知仅说明需要检查设备变化，不包含完整设备编号或关系图；
- 点击通知只打开应用，界面展示点击时 Engine 当前指定的变化；
- 通知不可直接作决定；
- 普通离线、自动补齐和后台重试不通知。

通知不可用或权限关闭不影响应用内强制流程。

## 9. 平台界面

- 共享文件只定义属性和纯展示模型，不使用 `Platform.OS` 分支。
- iOS 使用 `@expo/ui/swift-ui`、系统颜色和现有 iOS 公共组件。
- Android 使用 `@expo/ui/jetpack-compose`、Material 3 颜色和现有底部/弹层基础设施。
- 平台实现各自拥有样式、返回和呈现行为。

## 10. 隐私

日志、分析和通知不得包含设备名称、完整设备编号、变化编号、关系图或用户内容。错误日志只记录
操作名和稳定错误类别。移动端不持久化完整设备信任快照或选择内容。

## 11. 测试矩阵

### 自动测试

- 冷启动完整查询恢复待决定变化；事件只触发查询。
- 读取乱序、决定与读取竞态、失败后只刷新、重复点击和非法选择。
- `stateChanged`、`alreadyCompleted`、本机确认和下一变化收口。
- 变化编号切换重置选择，只显示允许选择。
- 不可关闭行为、长期状态优先级、重复名称和普通离线无警告。
- 前后台恢复、运行期通知去重、点击后读取当前变化、权限关闭仍显示应用内界面。
- iOS/Android 原生桥接公开同一接口并映射同一事件。

### 运行验证

- iOS 模拟器：启动、决定界面、不可下滑、前后台恢复、通知点击。
- Android 模拟器或真机：启动、返回键、重复点击、前后台恢复、通知点击。
- 最终三设备：移动端与另外两台设备分别验证应用变化、保留形成不同空间、本机退出、终止重启
  恢复，以及决定后的接收方内容交换。

## 12. 完成定义

代码交付需满足自动测试、类型检查、两端构建和可用设备上的交互验证。正式产品验收还必须有包含
本契约的 Engine 正式发布和三台真实设备的接收方验证。两者分别报告，不能用前者替代后者。
