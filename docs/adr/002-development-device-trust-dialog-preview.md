# ADR-002: 在开发包中安全预览设备关系决定界面

状态: 已决定，已实施

日期: 2026-08-18

最后更新: 2026-08-19

## 背景

设备关系决定界面是一个全局、不可绕过的界面。Engine 提供当前变化、允许的选择和
每种选择的影响；移动端负责展示这些事实、二次确认高影响选择，并把用户决定交回
现有空间服务。

当前 `DeviceTrustDecision.*` 的界面与真实运行状态直接连接。Android 的界面内容在
内部读取正式控制逻辑，正式控制逻辑又直接读取统一空间状态并调用空间服务。因此，
为了预览而临时写入统一空间状态有两个问题：应用刷新可以立刻覆盖假状态；用户点击
预览按钮也可能进入真实决定流程。

开发时需要在 Android 开发机和 iOS 模拟器或开发机上反复查看和操作这个界面，包括
普通选择、二次确认、提交中、失败、状态变化、长设备名和多设备滚动。预览必须使用
正式界面，不能复制一套演示界面，也不能为了制造场景而改变 Engine、数据库、真实
空间或统一空间状态。

## 决定

设备关系决定界面采用“唯一全局宿主、两种状态来源”的结构。

### 1. 保留唯一全局宿主

`App.tsx` 继续只挂载一个 `DeviceTrustDecision`。正式决定和开发预览不得分别挂载两个
界面，也不得同时显示。Android 继续使用不可绕过的原生对话框；iOS 使用挂在应用根部
的全屏遮罩，不再申请第二个系统弹窗位置。

平台界面继续由 `DeviceTrustDecision.android.tsx` 和
`DeviceTrustDecision.ios.tsx` 分别负责。两端使用相同的显示与操作接口，但各自保留
现有 Material 3 / Jetpack Compose 和 SwiftUI 实现、主题、滚动、按钮及关闭规则。

### 2. 显式分开显示与真实操作

平台界面只消费一个“决定会话”，不再在界面内容内部自行取得正式空间状态。该会话
只暴露界面实际需要知道的内容：

- 当前要展示的变化、设备和选择影响；
- 当前选项与正在确认的选项；
- 是否正在提交、是否失败、状态是否已经变化；
- 选择、继续、确认和取消确认四个操作。

正式适配器继续使用现有 `useDeviceTrustDecision`、统一空间状态和空间服务。预览适配器
只使用固定场景和当前进程内的临时状态。两个适配器满足同一个接口，平台界面不知道
自己显示的是正式决定还是预览。

不得给正式组件增加 `preview` 开关，不得让调试页面传入空间快照、服务、任意回调或
任意 JSON。调用方只能选择一个预先登记的场景。

### 3. 先选择，再继续执行

设备关系决定不得把选择和执行放在同一次点击中。界面采用以下固定顺序：

1. 有两个选择时默认不选中任何一项，避免替用户决定；只有一个选择时自动选中。
2. 每个选择使用完整可点击的单选行。点击文字、状态说明或右侧空白只改变当前选择，
   不提交决定，也不打开确认界面。
3. 没有选择时“继续”不可用；选中后，“继续”才执行普通选择或进入二次确认。
4. 普通选择直接执行。保留本机当前列表，以及会让本机退出同步的选择，必须再显示
   一次后果确认。
5. 确认按钮直接说明后果，例如“保持当前列表并停止同步”或“让这台手机退出同步”；
   不使用“确定”“应用变化”等需要用户自行推断含义的词。
6. 从确认界面返回时保留已选项。正式决定完成后由现有结果流程接管；预览决定完成后
   关闭预览。失败预览点击“重试”后仍停留在选择界面，便于继续检查。

主标题说明用户正在选择“这台手机要同步的设备”。选项标题使用“使用某设备的列表”
或“保持这台手机当前的设备列表”，影响摘要只展示实际存在的“仍会同步”“将不再同步”
和“恢复同步时需要重新邀请”，不展示空的状态行。

### 4. 预览与正式状态完全隔离

预览适配器必须满足以下规则：

1. 不读取、不写入统一空间状态，不创建第二份空间状态或待决定队列。
2. 不导入空间服务、应用运行时或原生 Engine，不持有任何真实决定函数。
3. 所有选择、确认、取消和模拟重试只改变内存中的预览会话。
4. 预览不持久化，不跨重启恢复；关闭后立即销毁。
5. 预览可以复用纯展示转换，但不能根据在线状态、设备数量或旧名单推断设备关系。
6. 场景只能使用代码中定义的枚举；不接受真实设备标识、邀请码、任意设备名或外部
   传入的结构化数据。

预览开始前若已有正式决定、正式提交或操作结果，拒绝打开预览。预览期间若正式决定
到达，立即关闭预览并显示正式决定。预览不得遮挡、延迟、清除或改写正式决定。

### 5. 两个平台都从开发者设置进入

Android 入口放在现有“设置 > 开发者选项”中，使用完整可点击的设置行和场景选择弹层。
iOS 开发包在设置首页显示“开发者选项”，进入后使用完整可点击的原生菜单选择相同的
固定场景。两个调试页面都只负责发出“打开某个场景”的请求，不拥有弹窗布局、设备
影响摘要或决定状态，场景仍由唯一全局宿主显示。

iOS 设置本身由原生弹层承载。开发子页不得直接呈现另一个弹窗；它只把场景选择报告给
稳定的设置页。设置页确认预览当前可打开后，立即建立根部预览并关闭设置。根部遮罩在
设置弹层退场后自然可见，不需要再申请一个系统弹窗，也不依赖关闭回调与导航退场事件
之间的时序。这样不会在动画子页中形成嵌套弹窗或重复的呈现状态。

入口以应用变体为准，只允许非生产应用身份。不能只依赖可持久化的“调试模式”开关，
也不能把 `__DEV__` 当作唯一隔离条件。生产包不显示入口，不接受预览请求。

本 ADR 不新增独立预览路由。以后如果需要命令行直达，可在同一个场景枚举
和打开接口上增加仅开发包可识别的固定链接；链接仍不得接受任意预览数据。

### 6. 首批场景覆盖不同的界面分支

首批场景至少包括：

1. 两个选择均可用的普通变化；
2. 只允许一个选择；
3. 保留本机当前空间的二次确认；
4. 采用变化会让本机退出空间的二次确认；
5. 正在提交；
6. 提交失败后可重试；
7. 状态已经变化或已经由其他设备完成；
8. 长设备名、多设备和需要滚动的内容。

浅色、深色和语言使用应用当前设置，不复制成另一套业务场景。增加新场景时必须对应
新的显示或交互分支，不能为了排列组合无限扩张场景表。

## 接口与顺序约束

决定会话必须保持以下不变量：

- 没有当前显示内容时不展示弹窗，任何操作都无效。
- 当前选项和确认选项必须属于当前变化允许的选择。
- 多选项变化默认没有当前选项；单选项变化自动选择唯一选项。
- 选择只更新当前选项，必须由单独的“继续”操作推进流程。
- 变化编号改变时重置选项并清除确认状态。
- 保留本机当前空间，以及会让本机退出空间的选择，必须先进入二次确认。
- 提交期间忽略重复操作；同一次用户操作最多提交一次。
- 取消确认只返回当前选择页，不关闭正式决定。
- 正式决定仍禁止 Android 返回键、点击外部关闭和 iOS 下滑关闭。
- 预览允许退出，但退出只销毁预览会话，不刷新空间，也不改变任何设置。
- 正式操作结果继续优先于下一项决定；预览不得改变现有结果页顺序。

正式提交失败、变化已过期或选择已经不再允许时，继续采用现有空间服务发布的最新
结果。平台界面不自行重试旧变化，也不把预览场景用于正式错误恢复。

## 结果

### 正面结果

- 开发者可以在 Android 开发机和 iOS 模拟器或开发机上稳定、重复地打开同一个正式
  弹窗。
- 界面修改只发生在一处，正式流程和预览不会逐渐产生两套视觉结果。
- 预览按钮没有取得真实空间操作的路径，误点不会改变设备关系。
- 不需要修改 Engine、数据库或真实设备拓扑来制造界面状态。
- 当前只增加完成这一需求所需的少量开发能力，不引入新的应用外壳或依赖体系。

### 代价与边界

- 需要把目前隐藏在界面内部的决定会话接口明确下来，并维护一组固定预览场景。
- 预览只能证明界面、文案、滚动和本地交互，不能证明 Engine 决定、多设备传播、
  重启恢复或正式包行为。
- iOS 选择场景后会建立根部预览并退出设置页；设置退场后预览自然可见，完成或关闭后
  不会自动回到开发者选项。这是保持唯一全局宿主并避开系统弹窗竞争的有意取舍。
- 预览期间到达正式决定会中断当前预览，这是保护真实流程的有意行为。

## 不采用的方案

### 向统一空间状态写入假快照

拒绝。应用启动和状态事件会覆盖假快照；更重要的是，现有控制逻辑可以把预览点击
交给真实空间服务。这种方法既不稳定，也不能证明隔离。

### 复制一套演示弹窗

拒绝。复制布局会让文案、滚动、按钮状态、确认规则和平台样式逐渐偏离正式界面，
预览通过也不能说明正式界面正确。

### 给正式组件增加 `preview` 模式参数

拒绝。模式参数会让正式状态、假状态和真实操作在同一个调用接口中任意组合，调用方
必须理解更多约束，且一次错误传参就可能破坏隔离。

### 新增独立预览页面或导航路由

拒绝当前采用。正式决定已经由全局宿主持有；再建页面会引入第二种呈现与关闭路径。
现有 Android 和 iOS 开发者设置足以选择场景，唯一宿主足以展示预览。

### 使用 Expo 开发菜单扩展

拒绝当前采用。项目没有直接使用对应开发菜单库，且场景选择仍需要额外界面。现有
开发者设置已经可发现，不需要仅为一个入口增加依赖。

### 引入 Storybook React Native

拒绝当前采用。Storybook 的真实设备预览、场景目录和独立入口是成熟方案；官方的
入口切换也能让正常应用不包含 Storybook 代码。但当前只有一个需要预览的全局弹窗，
项目尚无 Storybook，当前兼容版本还会增加新的应用外壳和依赖。此时引入它超出最小
需求。

当项目需要为多个独立界面维护场景目录、搜索、参数控制、共享预览或自动视觉回归时，
应重新评估 Storybook。届时仍应复用本 ADR 的显示接口和无真实操作的预览适配器，
不能恢复假快照注入。

## 实施范围

本次实施包括：

- 调整 `DeviceTrustDecision.android.tsx`，让界面内容消费显式决定会话；
- 对齐 `DeviceTrustDecision.ios.tsx` 的同一接口，并把全局承载方式改为应用根部全屏遮罩；
- 保留 `useDeviceTrustDecision.ts` 作为正式适配器；
- 在开发工具目录增加场景定义、内存预览适配器和打开/关闭协调器；
- 在 Android `DebugSection` 增加完整可点击的场景入口；
- 在 iOS 设置中增加开发包专用入口和原生场景菜单，并由稳定的设置页负责建立预览和
  关闭设置；
- 增加生产变体门禁、依赖约束和回归检查；
- 更新当前锁住“平台界面必须直接调用正式 hook”的结构测试，使其检查唯一宿主、
  共同显示接口和正式适配器连接，而不是继续固定现有耦合。

不得修改 Engine 接口、设备关系算法、统一空间状态结构、正式决定顺序或结果页规则。
不得把预览状态加入持久设置。

## 验收标准

1. `App.tsx` 仍只有一个全局设备关系决定宿主；正式决定和预览绝不同时显示。
2. Android 和 iOS 的正式流程与全部预览场景分别经过同一份平台界面内容，不存在复制
   的弹窗布局。
3. 自动检查遍历全部预览场景并执行选择、确认、取消、退出和重试后，真实空间服务
   调用次数为零，统一空间状态前后完全一致。
4. 依赖检查禁止预览适配器导入统一空间状态、空间服务、应用运行时或原生 Engine。
5. 正式决定存在时无法打开预览；预览期间到达正式决定时，预览立即退出且正式变化
   的编号、允许选择和当前状态没有被改写。
6. 生产应用身份不显示预览入口，也不能通过内部调用或未来固定链接打开预览。
7. Android 和 iOS 开发者设置中的预览行为整行可点，包括右侧空白区域，并有回归检查。
8. 普通选择、单选项、两种二次确认、提交中、失败、状态变化、长名称和多设备滚动
   均有自动检查。
9. 现有正式行为检查继续通过：高影响选择必须确认、提交不重复、变化更新会清除旧
   确认、操作结果会挡住下一项决定、正式界面不能被系统手势绕过。
10. 在 Android 开发机上逐个打开首批场景，实际点击选择、确认、取消、退出和重试，
    检查浅色、深色、长文本和滚动；应用日志中没有真实决定请求。
11. 在 iOS 模拟器或开发机上实际进入开发者选项，展开全部场景，打开主界面并检查选择、
    继续、确认、关闭、失败重试和长内容滚动；设置页不得遮住主界面，系统日志不得出现
    同时呈现两个弹窗的冲突。
12. iOS 类型检查和现有决定界面测试继续通过，确认正式内容、决定顺序和不可绕过规则
    保持不变。
13. 验收报告必须明确：上述结果只证明预览隔离和界面行为，不代表真实多设备决定、
    Engine 端到端或正式包发布验收。

## 实施状态

Android 与 iOS 开发包入口、八个固定场景、预览隔离、正式决定优先级和“选择、继续、
风险确认”交互均已完成。Android 开发机已实际检查双选项、单选项、两种风险确认、
提交中、失败重试、状态变化、长名称与滚动，并检查浅色和深色显示。整行选择、“继续”
的禁用状态、返回后保留选择、完成后关闭预览均已实际点击确认。

iOS 模拟器已实际进入开发者选项，并从设置行右侧空白处展开包含八个场景的原生菜单。
真机反馈暴露了第二个系统弹窗无法稳定出现的问题；模拟器日志进一步确认系统拒绝在
设置页面仍占用展示位置时呈现全屏弹窗。iOS 全局决定界面现已改为应用根部全屏遮罩。
从开发者选项选择双选项场景后，设置页正常退出，主界面完整显示；选择“保留当前列表”
并点击“继续”后，风险确认界面正常出现。系统日志未再出现弹窗展示冲突，内容、按钮和
长文案没有重叠。iOS 真机仍需安装当前构建后复验，不能用本次模拟器结果替代。

自动检查覆盖生产应用身份拒绝预览、正式决定打断预览、预览不调用真实决定服务、真实
空间状态前后不变，以及正式决定原有的确认和提交规则。验证期间的应用日志中没有出现
真实设备关系决定请求。最终完整检查通过 139 组、975 项。

尝试向 `marks iPhone` 安装当前开发构建时，系统无法建立到已配对设备的连接通道，构建
在选择目标设备阶段停止，手机上的应用没有被覆盖。因此本次仍不把 iOS 真机列为通过；
恢复 USB 数据连接并解锁设备后，需要重新安装并执行同一入口到主界面的点击验收。

这些结果只证明开发预览的隔离、界面显示和本地交互；不证明真实多设备决定、Engine
传播与恢复、正式包入口或发布结果。
